# 人生の断面図：チャンネル運営スキル

ヒロキ（機械設計エンジニア歴約25年）の3つ目のチャンネル。既存の2チャンネル（バグってる平行世界・ゼロからAI副業）とは混ぜない。AIの使い方の具体的な手順は「ゼロからAI副業」の担当で、ここでは「見えている世界の比較」までにとどめる。

このスキルの中身は、2026年11月時点の YouTube の実データ（夜ふかし解剖室39本＋競合5チャンネル約800本の再生数、上位動画の字幕全文）から作った。**再生数の数字は調査時点のもの**。古くなっていたら、YouTube のチャンネルページ（人気順・古い順）で取り直す。

## 0. いちばん大事な3つ

1. **テーマで決まる**。浮き世の解剖ラボは外れテーマで100本出して中央値729回。思考のレグラボは当たりテーマ23本で173万回。**当たるテーマ一覧（2章）にないものは作らない**
2. **主戦場は長尺（10〜15分）**。このジャンルのショートは長尺の1/7しか見られていない（大神さん：ショート中央値6,900回、長尺4.65万回）。ショートはテーマの反応を見るのと、長尺への入口に使う
3. **誰も責めない**。どの段にも強みを書き、最後は救いで終える。下の段の人が見て嫌な気持ちにならないこと

## 1. チャンネルの設定（変えない）

- 名前：**人生の断面図**（2026-11-24 ヒロキが確定。予備案は使わない）。決めゼリフ：冒頭「あなたは、何階ですか？」／最後「あなたは何階でした？」
- 見た目：紺の方眼紙（#0A142E）にビルの断面図。線はシアン（#78C8FF）、"差"と「あなたの階」だけアンバー（#FFB020）。夜ふかし解剖室の模型・黒猫、赤黒の文字には似せない
- 段は**ビルの4つの階**（1階が一番下）。人物は基本**同じ年に入社した同期4人**（ケンタ300万・ユイ500万・ショウ700万・リク1000万、45歳）。テーマによって「同じ部署の4人」「同じ年に就活した4人」も可
- 締めの決まり文句（毎回同じ）：「今夜の断面図は、ここまで。人生の断面図では、気になっていた"差"を、研究と数字をもとに、1枚ずつ図面にしていきます。今夜の話が少しでも役に立ったら、高評価とチャンネル登録で、このチャンネルを支えてもらえると嬉しいです。次の図面を描いて、お待ちしています。」
- 概要欄に毎回：出典（論文名）、「研究からわかるのは平均の傾向です」「登場人物は架空です」

## 2. テーマの選び方

**当たる（実績順）** ※2026-11-25 更新：1週間の伸びでは「会社」が最強（レグラボ27本で6日間+56.5万）
0. **会社の理不尽を仕組みで説明**：「〜した会社は、最後にどうなるのか」（因果応報型）、「AとB、10年後に勝つのはどっち？」（二者択一の未来予測、レグラボ新作が6日で22.3万）
1. お金の階級：年収・世帯年収・富裕層・貯金額（夜ふかし62.5万、浮き世11.7万）
2. 会社の中の差：役職・人事評価・会社の大きさ・問題社員・辞める人（レグラボ47.8万／27.4万／26.5万、10分前後）。**ヒロキの会社員経験が一番活きる**。ビルの4階＝平社員・係長・課長・部長
3. 世代：特にZ世代と氷河期世代（夜ふかし42.6万、のら学者13.1万）
4. 頭の良さ・IQ（夜ふかし20.4万・21.8万、大神39.8万）
5. 将来の不安：独身の老後・弱者男性・アンダークラス・境界知能（のら学者17.6万）
6. 自分を変える科学：学び方・努力・習慣（Motocrab 55.6万）

**外れる（作らない）**
- 順位のない一般心理「なぜ人は〜」（浮き世 50〜70回）、性格・メンタル・言語化（夜ふかし 5,682〜8,393回）
- 抽象的な哲学・社会（Motocrab 1,615回）
- ハウツー：年金・健康法・生活の知恵（のら学者「年金は払い損か」280回）
- 雑談・質問コーナー
- **2段だけの比較**（メンタル強弱、4月／3月生まれ、生まれた順番）は弱い。段は3〜4つで、数字かラベルを付ける。例外：**「金持ちと貧乏人」×誰でも観察できる違い**（見た目・物の量・他人への関心）は2段でも当たる（えるくる35.1万・8.9万・7.2万）
- 生まれた順番は夜ふかし（4,619）・えるくる（4,600）の両方で外れ → 作らない
- 当事者が一部の人だけの軸（定年前後、NISA、恋愛中）は弱い

**タイトルの言葉で10倍変わる**：同じテーマでも、自分が当てはまる**具体的な分類名**を並べると当たる（えるくる「『親が自営業』『親がサラリーマン』でどんな違いが出るのか？」39.4万 ／ 夜ふかし「親の仕事は、子どもの人生にどんな影響を与える？」9,670）

**掛け算**：単体の軸で当たってから、当たった軸どうしを掛ける（年収×結婚など）。掛け算は単体の1/3〜1/10の再生になりやすいので、本数を増やす役と考える。

## 3. 4つの型（テーマで選ぶ）

| 型 | テーマ | 骨組み |
|---|---|---|
| **物語型** | 年収・貯金・IQ | 4人の階を1階から順に。1人＝1つの階＝1つの理由。後半で4人が集まる場面→救い |
| **年表型** | 世代・年代 | 各世代を「生まれた年→子ども時代→学校→就職→今」でたどる。各段で「〜と思いやすい」。最後に信念3つ＋強み |
| **比べる表型** | 会社の大きさ・役職・人事評価・学歴 | 同じ5項目（お金→ふだんの仕事→休み→外からの見られ方→50代から）を階ごとに順に。「なぜ」は最後にまとめて1章（クイズ→数字→理由2つ） |
| **人生の断面図型** | 老後・独身・氷河期の一生・年収300万の一生 | 1人の人物を年齢順に追う（1階＝40代…4階＝75歳）。1つの小物を通す（のら学者の合い鍵）。最後に結末を2つ見せる |

## 4. 長尺の台本ルール（10〜15分、ナレーション約3,000〜4,500字）

**冒頭60秒**
1. 対比する数字2つ（公的統計）か、意外な事実を1つ
2. 1行の言い切り（タイトルの答えの予告）
3. 同じスタートの4人＋懐かしい具体（あとで回収する伏線）
4. 何年後・何歳＋段を明かす
5. 責めない宣言（「この差は、努力だけで決まったわけじゃない」）
6. 「今夜は、このビルを1階から順にのぼって…」
7. 数の予告（「理由を4つ、図面にしていく」）
8. 最後に分かることの約束

**各章（1つの階）**
1. 「最初の部屋は、1階のケンタだ。」
2. 暮らしを細かい数字で（家賃・手取り・時刻）
3. 公的統計でその人の位置を示す（「〇〇の平均は〜。ケンタはちょうどそのくらいだ」）
4. 心の声をかっこで
5. 意外なひっくり返し
6. 研究を物語で：国名から入る→「すると／ところが」→数字1つ→責めない言い直し（「知らないのでも、計算が苦手なのでもない。〜だけなのだ」）
7. 外からの誤解→その階の強み（「ほかの階からは〜に見えやすい。けれど〜。ケンタの強みは〜力だ」）
8. 「これが、〇〇の部屋から見える景色だ。」→「理由、〇つめ。つまり、〜」（ここで音を止める）
9. 次の章への問いか予告（「では、年収が500万あれば…？」）

**全体に入れるもの**
- 視聴者に1問（3択か何割か。「画面を止めて、考えてみてほしい」）
- 思い込みを数字で1回ひっくり返す（「答えは、逆だった」）
- 「その心配は、半分は正しい」で半分認めてから、残りをひっくり返す
- 視聴者に自分で確かめさせる（「あなたの〇〇を△で割ってみてほしい」）
- 2人を1文で対にする（「ケンタは時間を使ってお金を守り、リクはお金を使って時間を作る」）
- 最後に冒頭の言葉や小物を回収する
- 文体：1文を短く。「〜だ。」の言い切り。断定しすぎない所は「〜と思いやすい」「〜傾向がある」

**研究の選び方**：`references/使用済みの研究.md` で、元チャンネルが使ったものと重ならないか確認する。数字・巻号は原文で確認するまで【要確認】と書く。数字をでっち上げない。

例：`references/長尺台本の例_年収と時間.md`

## 5. ショート（40〜50秒）

- **0〜1秒**：誰でも分かる出来事を「動き＋音」で見せる。第一声は1秒以内に言い切る。テロップは7〜10文字（例：スマホが割れる「ガシャッ」「スマホが割れた。」「修理代 3万円」）
- 1〜5秒：4人の写真が割れてビルの4つの階へ（「トン」×4）
- 5〜25秒：1階から順に心の声（1人5秒）
- 25〜40秒：研究を1つ
- 40〜50秒：救い→「あなたは何階でした？」→最後の絵を冒頭の絵と同じにしてループ
- 長尺ができたら、ショートは**長尺の一番強い場面の切り出し**にする（新作は作らない）。長尺1本→ショート5本（各場面1本＋結末の手紙1本）。最後は「本編で、4人の20年をたどる。あなたは、何階でした？」で本編へ誘導し、投稿時に関連動画へ長尺を指定する。例：`channel_produce/shorts/make_shorts_6to10.py`

**絵は説明なしで分かること**（2026-11-25 視聴者コメント「迷路の設計がよくわからん」👍3 より。ショート3 IQ）
- たとえ（迷路・階段など）を使うなら、ナレーションかテロップで**1回はっきり言う**（例：「上の階ほど、迷路を上から広く見下ろせる」）
- **同じもの**の見え方の差を見せるなら、最初に全体を1回見せ、各階は同じ絵の一部を隠す・明かすで描く（別々の絵に見えないように）
- 迷路ならスタート・ゴール・本人の位置、グラフなら軸と単位など、**それが何かが分かる目印**を必ず入れる
- 1本のたとえは1つ。ビルの階＋迷路のように2つを重ねない
- 画面の文字は縦動画で最小40px（スマホで読めない小さな注記に意味を持たせない）
- 確かめ方：音を消して各場面を1秒ずつ見て、何の絵か言えるか

例：`references/ショート台本の例_年収.md`（自動配置ツールの script.md 形式。「テロップ：」「効果音：K01 +0.35」の指示付き）

## 6. タイトル・説明欄・サムネ

- タイトル：「なぜ〇〇は、〜のか」の問い。答えは書かない。40文字以内。数字を入れる（「890万人」「S・A・B・C」）。**【組織行動学】【行動経済学】など学問名を付けるテストをする**（競合3チャンネルが使用、夜ふかしは未使用）。「9割が知らない」は使わない
- 説明欄：中身の一言→「あなたは何階？」→出典→注意書き→チャンネル紹介→ハッシュタグ3〜5個
- サムネ：Midjourney で文字なしの絵（縦に切ったビルの断面のミニチュア模型、紺の方眼、夜の部屋の灯り）→ **Pillow で文字を入れる**（`channel_produce/shorts/make_thumbs_mj.py`。GPT Image より安く、字も崩れない）。上に問い2行（白の極太、キーワードだけアンバー）、そのすぐ下に「〇〇別｜人生の断面図」の帯。ヒロキの好み（2026-11-25）：設計図風の線画ではなく、この**ミニチュア模型の写真風**
- **ショートのサムネの安全範囲**：チャンネルのショート一覧は 9:16 の上下を約8%ずつ切って見せる（2026-11-25、1行目が隠れていた）。文字と帯は**上から230px より下**にまとめ、一番下には何も置かない（切られるうえ、1階の部屋が隠れる）
- Midjourney は1回で4案出るので、使わなかった案を別の回のサムネに回す（ショート6〜10は1〜5の残りの案で作り、追加クレジット0）
- Midjourney と GPT Image は TapNow（接続済みの場合）から使える。費用は TapNow のポイント（目安：Midjourney 1回4案で約20、GPT Image 1枚約25）。midjourney.com をブラウザで自動操作するのは利用規約違反なのでしない

ひな形：`references/タイトル_説明欄_サムネ.md`

## 7. 失敗しないためのルール（毎回チェック）

1. テーマは2章の「当たる」に入っているか
2. 段は3〜4つ（または1人の一生を年齢で）。数字かラベルが付いているか
3. どの段にも強みがあり、最後は救いで終わるか
4. 研究・統計は公的なものか論文で、概要欄に出典があるか。元チャンネルと重なっていないか
5. 長尺は10〜15分か。冒頭1分で「何が分かるか」を約束しているか
6. 1本ずつで判断していないか（**10本ごとに**数字を見る）

**方向転換の目安**
- 長尺10本で1万回超えが1本もない → テーマ・サムネ・タイトルを見直す（上位チャンネルのサムネと並べる）
- 長尺20本で10万回超えが1本もない → 型を変える
- 長尺が8〜10本たまったら、1〜2時間の「聞き流し総集編」を作る（大神さんは総集編で100万回前後×3本）

## 8. 投稿後の分析

- 24時間以上たってから見る：冒頭3秒の維持率、平均再生率（ループで100%超え）、コメント数、インプレッションのクリック率
- 観測値（事実）と仮説を分けて書く。一度に変えるのは1つだけ
- 当たりは全体の1〜3割が普通（どのチャンネルも同じ）。外れても型をすぐには捨てない
- **コメントは貴重な実測**（ヒロキ 2026-11-25）。「分からない」系のコメントは、いいねの数も見て、次の台本・絵のルールに必ず反映する。記録は `references/視聴者の反応.md`

## 9. 制作の道具（リポジトリ `my-first-project` があるとき）

**ショートを投稿できる mp4 まで仕上げる流れ（2026-11-24 確立）**
1. ナレーション：TapNow の `create_audio`（mode speech、model **elevenlabs-v3**、voice **george**＝声A。ヒロキは ElevenLabs のAPIキーを渡さない方針なので TapNow 経由）。**1本のショートを1回で読ませ、場面の間に ` [long pause] ` を入れる**（場面ごとに分けて頼むと TapNow の回数制限に当たる）。1回あたり約0.05ポイント
   - 読み間違えやすい語はかなにしてから読ませる：IQ→アイキュー、AI→エーアイ、Z世代→ゼット世代、4人→よにん、1000万→せんまん、1000人→せんにん、7つ→ななつ、1つ→ひとつ、何階→なんかい、何世代→なんせだい、1階→いっかい、稟議→りんぎ、判子→はんこ
2. `python channel_produce/shorts/split_narration.py <フォルダ> <ナレーション.mp3>`：無音と各場面の文字数から境目を選んで `narr/S01.mp3`… に切る（短い間を境目と取り違えないよう、文字数から予想した位置に近い無音を選ぶ）
3. `python channel_produce/shorts/render_final.py <フォルダ>`：場面の長さ＝ナレーション＋間に合わせて映像（動く mp4／画像はゆっくりズーム）・テロップ（「や（の前、、。の後で改行）・効果音を組み、-14 LUFS にそろえて `完成_ナレーション入り.mp4` を出す（Resolve なしで投稿できる）
4. サムネ：Midjourney（TapNow の midjourney-v8.2、9:16、4案）→ 一番良い案を選ぶ（上に文字の空き、4階がはっきり、1つの階がアンバー）→ `make_thumbs_mj.py` で文字を入れる → 1080×1920 の `サムネイル.jpg`。採用：1C・2D・3D・4C・5C、6〜10は 1A・4A・1D・4D・1B（各フォルダの `サムネ素材_mj.png`）
- TapNow の生成物は `files.tapnow.media` から curl でダウンロードできる（環境の許可済みホスト）

**長尺を仕上げる流れ（2026-11-25 第1弾で確立）**
1. 台本 script.md：テロップの指示は書かない（字幕を自動で入れる）。場面は [a][b]… で細かく切る（1場面＝1枚の絵、5〜20秒）
2. 絵：`channel_produce/long/make_long01.py` の部品（card・reason・research・room・bldg・envelopes・ties・snow_room など）で 1920×1080 の PNG を作る（`bp.W, bp.H = 1920, 1080`）。コンタクトシートで重なりを確かめる
3. ナレーション：シーン2〜3個ずつを1回で読ませ（約1,000字＝4回）、`split_narration.py <フォルダ> <mp3> S08,S09` でシーンを指定して切る
4. `render_final.py <フォルダ> --landscape --subtitles`：横長・字幕焼き込み（。？！で区切り、30字超は真ん中の、で分ける）。62枚で20〜30分かかる
5. サムネ：Midjourney 16:9（ビルを右3分の1、左は空ける）→ `make_long01_thumb.py` で Pillow で文字を入れる（1280×720）

**クレジット節約（2026-11-25 ヒロキの要望）**：絵は Pillow（無料）、ナレーションは TapNow ElevenLabs（長尺4回＋ショート5回で約0.5）、Midjourney は長尺サムネの1回だけ（約20）。文字入れは GPT Image を使わず Pillow（無料、字も崩れない）。ショートのサムネは Midjourney の残りの案＋Pillow の文字（`make_thumbs_mj.py`）。費用は作る前と後に get_tapies_balance で残高を見て記録する（ナレーションの単価は文字数で変わるため、見積もりより実測を使う）

- 台本 script.md → `autoedit.py "<動画フォルダ>" --motion alternate` で DaVinci Resolve に組み上げ（画像はゆっくりズーム、テロップは Text+、効果音は se/K01_〜.wav）
- ショートの素材：`channel_produce/shorts/make_short01.py`、`make_shorts_2to5.py`（絵の部品は `blueprint.py`、効果音は `sfx.py`）
- アイコン・バナー：`channel_produce/make_brand.py`
- 資料のページ：`channel_produce/make_page.py`（Artifact に公開）
- 競合の数字を取り直す：`yt-dlp --flat-playlist -J --extractor-args "youtube:lang=ja" "https://www.youtube.com/@<handle>/videos"`（YouTube がロボット確認を出したら回数を減らす）

## 10. このスキルの更新（ヒロキの指示：毎回）

分析の結果やヒロキのフィードバックで、次に作るときにも使うべきことが分かったら、**その会話のうちにこのスキルを更新する**。聞かれるのを待たない。

**更新するもの**
- 新しく分かった法則・型、当たる／外れるテーマ（数字の根拠と調べた日付を付ける）
- 投稿後の実測（再生数・維持率など）と、そこから分かったこと。予想と違ったら、古い記述を直す
- ヒロキの好み・決めたこと（見た目、言い回し、やらないことなど）
- 台本で使った研究（`references/使用済みの研究.md` の表に足す）
- 道具の使い方の変更

**更新しないもの**：一度きりの作業メモ、確かめていない思いつき（仮説として書くなら「仮説」と明記する）

**やり方**
1. 決まりごと・ルールは SKILL.md の該当する章を直す（150〜250行に収める。長い根拠やデータは references/ に入れる）
2. データ・分析の詳細は references/ のファイルに足す
3. 古くなった数字や外れた予想は、残さずに書き直す（いつ、何で変えたかを1行残す）
4. リポジトリがあるときは `python tools/make_skill_zip.py` で zip を作り直し、コミットして push する
5. 返事の最後に「スキルを更新しました：〇〇」と1行で伝え、claude.ai 側にも反映したい場合は zip の再アップロードが必要なことを伝える
